# コードとファイルの示し方

## 引用

**説明にはコードの原文を出し、一字も書き換えない。** 原文は `git show <ref>:<path>` や `git diff <base>...<head> -- <path>` で取る。強調のマーカー（後述）を足すことだけは例外とする。

### 形式の選び方

hunk ごとに、消えた行があるかで選ぶ。ファイルが既存か新規かでは選ばない。

- 追加だけの hunk は、その言語のコードブロックで追加した行だけを示す。差分にしても `+` が付くだけで情報は増えず、シンタックスハイライトを失う。既存行は混ぜず、挿入位置は「`ListItems` の直後」のように散文で述べる
- 置換や削除を含む hunk は差分だけを示し、変更後の本文を併記しない。context は変更行の前後 1 行まで狭める
- 新規ファイルは本文で示す

1 つのファイルに両方の hunk が混ざるときは、ブロックを hunk の順に並べる。

生成物（mock、モデル、docs、lock ファイル、生成された README やスキーマ）は引用せず、どれが生成物で何が生成したかを一行述べる。生成コマンドが入力から作るもので、原文に下せる判断がない。機械的な差分（空白のみ、リネームのみ、一括置換）は形と規模だけ述べる。要約で済ませてよいのはこの 2 つだけである。

### 引用範囲

判断に必要な範囲へ絞る。周辺の定型（import、テストの table 全件）は省き、省いたことを述べる。長い追加は要点の 1 件を引用し、残りは件数と内容を散文で述べる。

周辺の既存コードは引用しない。依頼者は常にコードを開いて読んでいる。挿入位置は散文で、隣接コードの慣習は実測した数値（「N メソッド中 M が doc を持ち、1 行が a 件」）で、比較対象は行リンクで示す。例外は、既存コードの中身そのものが論点で、原文を読まないと判断できないときだけである。

### 強調

背景色は使えない（HTML の `style` は落ち、ANSI エスケープは文字になる）。行末に `// ← 追加` のようなマーカーを対象言語のコメント構文で置くか、引用を該当ブロックだけに絞る。

## パスとリンク

### 絶対パスで書く

パスを自動でリンクにするクライアントでは、裸のパスもバッククォートで囲んだパスも、作業ディレクトリ基準でリンクになる。実体の無いリンクは誤った場所へ連れて行くので、無いより悪い。

**パスは常に絶対パスで書く。** worktree でも本体クローンでも同じである。リポジトリのルート起点（`internal/foo/foo.go`）やリポジトリ名起点（`myapp/internal/...`）の相対パスは外れる。`git diff`、`git show`、`grep` の出力から写したら、作業中の worktree の絶対パスを頭に付ける。

```
/Users/<you>/projects/myapp/internal/foo/foo.go:12
/Users/<you>/projects/myapp-proj123/internal/bar/bar.go:40-43
```

ファイル名だけ（`bar.go`）はパスとして解決されないので壊れない。場所を示す必要がなければこれで足りる。

### 書く前に実体を確かめる

リンクを書く前に、そのパスが今あることを `ls` か `grep -n` で確かめる。

セッション限りの一時ディレクトリ（Claude Code の scratchpad など）を指すリンクは残さない。過去の応答や要約に出てくるそうしたパスは、会話を再開した時点で消えていることがある。複数のセッションにまたがる作業の worktree は、本体クローンの隣に `<リポジトリ>-<チケット>` の形で置く。scratchpad の worktree が消えていたら、`git worktree prune` してから同じブランチを永続パスへ作り直す。

### 行と範囲

行は `:line`、範囲は `:開始-終了` で書く。

**行番号は書くたびに、参照するファイルで実測する。** 記憶、差分のヘッダ、前回の応答から写さない。rebase、依存 PR のマージ、自分の修正でファイルは動き、ずれたリンクは依頼者を別のコードの前に立たせる。PR の変更行は、その PR のブランチをチェックアウトした worktree のパスで指す。

### リンク記法

リンク記法は短いラベルを付けたいときに使う。

```
[foo.go:12-14](/Users/<you>/projects/myapp/internal/foo/foo.go:12-14)
```

ラベルはリンク先のファイル名と行に合わせ、`ファイル名:行` を基本とする。同名ファイルが複数あるときは、層が分かる最小限を足す（`repository の bar.go`）。`...` で省略したパスはリンク先にしない。省略はラベル側で行う。

コードブロックの中は自動リンク化されないので、`git grep -n` の出力に現れる相対パスはそのままでよい。開かせたいパスはブロックの外に絶対パスで出す。

### PR、issue、チケット

PR と issue は完全な URL か、別リポジトリなら `owner/repo#123` で書く。裸の `#123` は書かない。コードを指すときの既定はローカルの絶対パスで、GitHub の blob URL は依頼者以外に渡すときや版を固定するときに限る。

依頼者への報告では、更新した先（PR、チケット、記録した場所）のリンクを通常のリンク記法で全部出す。片方だけ示すと、もう片方を直したことが見えない。
