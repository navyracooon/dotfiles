# 別エージェント（SA / PA / MA）

## 略称

| 略称 | 意味 | 旧称 |
| --- | --- | --- |
| **SA** | Standard Agent。標準のモデルで起動する別エージェント | OA |
| **PA** | Pro Agent。そのツールで使える最上位のモデルで起動する別エージェント | FA |
| **MA** | Managed Agents。問いを見て、SA / PA のどちらで何本立てるか、観点をどう割るかを親が決めて起動する | — |

MA と告げられたら、下の「本数と観点の割り方」に従って構成を決め、起動の前に構成（本数、各本の問い、SA / PA の別）を一行で述べてから起動する。

## ツールごとの起動方法

| ツール | SA | PA |
| --- | --- | --- |
| Claude Code | Agent ツール、`model: "opus"` | Agent ツール、`model: "fable"` |
| Codex | 既定のモデルのサブエージェント | 利用できる最上位のモデル（無ければ推論の effort を最大にした設定）のサブエージェント |

Codex の行は手段を確かめていない。実際に使うときに確かめ、この表を直す。対応するモデルが変わったときも、この表だけを直す。別エージェントを起動する手段が無い環境では、その旨を述べたうえで同じセッションで行い、コンテキストの切り離しが効いていないことを報告に明記する。

エフォートは **High が規定**である。依頼者が下げると言ったときだけ下げる。Claude Code の Agent ツールには effort の引数が無く、指定できるのは `model` だけなので、High はプロンプト側の指示として書く（浅いところで打ち切らず、主張は実測で裏を取らせる）。harness 側で固定するなら agent 定義（Claude Code の `~/.claude/agents/*.md`）に持たせる手もある。

SA / PA / MA と告げられたとき、および別エージェントを要求するスキル（`../self-review/SKILL.md` など）に従うときに使う。それ以外で自分の判断で生やさない。

## 主目的はコンテキストの切り離し

SA / PA を使う主な理由は、**現在のコンテキストに引っ張られない検討をさせること**である。親のセッションには「なぜそう書いたか」「どこまで調べて何を捨てたか」が残っており、その文脈で読み直しても書いたときと同じ目にしかならない。SR を別エージェントで回すのと同じ理由である。

したがって**親の仮説と結論は渡さない。** 渡すのは問い、対象、一次情報の所在、制約である。

- 渡す: 問い、対象のパスや PR 番号やチケットキー、一次情報の場所、**既に実測した数値そのもの**、守らせる制約
- 渡さない: 「たぶん X が原因」という見立て、親が出した結論、親が捨てた選択肢とその理由、こう答えてほしいという誘導、測った数値の解釈

切り離しが目的でない依頼（単に手数を増やしたい、調べ物を並列にしたい）でも同じ形で使えるが、その場合でも見立てを渡すと切り離しの効果は消える。渡すかどうかは意識して決める。

## 本数と観点の割り方

本数は任されている。判断の基準は次のとおり。

- 問いが 1 つで観点が分かれないなら **1 本**
- 独立した観点が複数あるなら**観点ごとに 1 本**を並列に起動する（Claude Code なら独立した Agent 呼び出しを 1 メッセージ内にまとめる）
- 結論が割れうる問い、外したときの損が大きい判断なら、**同じ問いを SA と PA の両方**に投げ、食い違いを見る
- 前段の結果が次の問いを決めるなら**直列**にし、前段の結果だけを次へ渡す（親の解釈は挟まない）

**同じ問いを同じモデルに複数投げない。** 差は出ず、多数決の材料にもならない。本数を増やす根拠は観点が独立していることだけである。

再検討をさせたいなら新しい起動で真っさらから始める。同じエージェントに詰めさせたいときだけ続きを送る（Claude Code なら SendMessage）（コンテキストが残るため、切り離しにはならない）。

## 渡すもの

1 本ごとに次を書く。

- **問いを 1 文で**。併せて成果物の形（結論と根拠、ファイルと行、数値の表など）
- **対象の場所**。リポジトリ、worktree のパス、PR 番号、チケットキー。既存の worktree があればそのパス、無ければ worktree を切らせる（Claude Code なら `isolation: "worktree"`）
- **一次情報の所在**と、既に測った値
- **制約**。push しない、本体クローンや他の worktree に触らない、無関係な未コミット変更を扱わない、外部サービスへ出さない、承認が要る操作をしない
- **読ませるスキルのパス**。エージェントはそれを読んでから始める
- **エフォート**（規定 High）

## 受け取り方

- エージェントの報告は**依頼者には見えない。** 親が要点を伝える。全文を転記しない。伝える地の文は AGENTS.md の Writing 節に従う。
- **報告を額面で信用しない。** パス、行番号、数値は親が引き直す。誤った報告や取り違えはありうる
- **SA と PA が食い違ったら、選ぶ前に食い違いの箇所を親が実測する。** 多数決にしない。どちらも外していることもある
- 既定はバックグラウンド。CI の監視など長く待つものは**親が持つ**（エージェントは終了とともに消える）
- 承認が必要な操作（push、外部への反映）は報告を受けた親が依頼者の指示で行う

## 使わない場面

- **単一の事実の確認。** ファイルもシンボルも分かっているなら自分で引く方が速い
- **親のコンテキストが判断に必要なもの。** UR の提示や、依頼者との対話の続き
- **依頼者の承認が要る操作の代行**
