# 別エージェント（SA / PA / MA）

## 略称

| 略称 | 意味 | 旧称 |
| --- | --- | --- |
| SA | Standard Agent。標準のモデルで起動する別エージェント | OA |
| PA | Pro Agent。そのツールで使える最上位のモデルで起動する別エージェント | FA |
| MA | Managed Agents。SA / PA のどちらで何本立て、観点をどう割るかを親が決めて起動する | — |

MA と告げられたら、「本数と観点の割り方」に従って構成を決め、本数、各本の問い、SA / PA の別を一行で述べてから起動する。

## 起動方法

| ツール | SA | PA |
| --- | --- | --- |
| Claude Code | Agent ツール、`model: "opus"` | Agent ツール、`model: "fable"` |
| Codex | 既定のモデルのサブエージェント | 利用できる最上位のモデル（無ければ推論の effort を最大にした設定）のサブエージェント |

Codex の行は手段を確かめていない。使うときに確かめ、モデルが変わったときも含めてこの表だけを直す。起動する手段が無い環境では同じセッションで行い、コンテキストを切り離せていないことを報告に書く。

**エフォートは High が規定**で、依頼者が下げると言ったときだけ下げる。Claude Code の Agent ツールには effort の引数が無いので、High はプロンプトに書く（浅いところで打ち切らず、主張は実測で裏を取らせる）。

使うのは、SA / PA / MA と告げられたときと、別エージェントを求めるスキル（`../self-review/SKILL.md` など）に従うときだけで、自分の判断では起動しない。単一の事実の確認、親のコンテキストが判断に要るもの（UR の提示、依頼者との対話の続き）、依頼者の承認が要る操作の代行には使わない。

## 主目的はコンテキストの切り離し

親のセッションには「なぜそう書いたか」「何を調べて何を捨てたか」が残っており、その文脈で読み直しても書いたときと同じ目にしかならない。SA / PA を使う主な理由は、これに引っ張られない検討をさせることである。

**したがって親の仮説と結論は渡さない。**

- 渡す: 問い、対象、一次情報の所在、既に実測した数値そのもの、制約
- 渡さない: 「たぶん X が原因」という見立て、親の結論、捨てた選択肢とその理由、答えの誘導、数値の解釈

手数を増やしたいだけの依頼でも、見立てを渡すと切り離しの効果は消える。

## 本数と観点の割り方

- 問いが 1 つで観点が分かれないなら 1 本
- 独立した観点が複数あるなら観点ごとに 1 本を並列に起動する（Claude Code なら Agent 呼び出しを 1 メッセージにまとめる）
- 結論が割れうる問い、外したときの損が大きい判断なら、同じ問いを SA と PA の両方に投げて食い違いを見る
- 前段の結果が次の問いを決めるなら直列にし、前段の結果だけを次へ渡す

同じ問いを同じモデルに複数投げない。差は出ず、多数決の材料にもならない。

再検討は新しい起動で真っさらから始める。続きを送る（Claude Code なら SendMessage）のは同じエージェントに詰めさせたいときだけで、切り離しにはならない。

## 渡すもの

1 本ごとに次を書く。

- 問いを 1 文で、成果物の形（結論と根拠、ファイルと行、数値の表など）とともに
- 対象の場所。リポジトリ、PR 番号、チケットキー、既存の worktree のパス。無ければ worktree を切らせる（Claude Code なら `isolation: "worktree"`）
- 一次情報の所在と、既に測った値
- 制約。push しない、本体クローンや他の worktree に触らない、無関係な未コミット変更を扱わない、外部へ出さない、承認が要る操作をしない
- 読ませるスキルのパス
- エフォート（規定 High）

## 受け取り方

- 報告は依頼者には見えない。全文を転記せず、親が要点を伝える
- 報告を額面で信用しない。パス、行番号、数値は親が引き直す
- SA と PA が食い違ったら、選ぶ前に食い違った箇所を親が実測する。多数決にしない
- CI の監視など長く待つものは親が持つ。エージェントは終了とともに消える
- 承認が要る操作（push、外部への反映）は、報告を受けた親が依頼者の指示で行う
