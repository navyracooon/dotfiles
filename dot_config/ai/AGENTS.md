# AGENTS.md

## Language

- 通常の回答は日本語で行う。ただし、ユーザーの依頼内容や既存文脈から、特定の成果物、引用、技術用語などで英語などが適切な場合はその限りではない。

## Workstyle

- 既存のコード、設定、コメント、ドキュメント、未コミット変更を尊重し、ユーザーが明示していない変更を勝手に戻さない。
- 不明点があっても、合理的に判断できる場合は作業を進める。
- 判断に迷う変更、破壊的操作、外部公開、認証情報に関わる操作は事前に確認する。
- 依頼の目的に沿って必要十分な範囲で変更し、差分の小ささだけでなく正しさ、保守性、既存コードとの一貫性を優先する。

## File Editing

- コメントやドキュメントの書き方は、既存コードベースの慣習を優先する。
- コメントは、コードだけから読み取れない意図、制約、背景、注意点を補う場合に限って追加する。
- 処理内容をなぞるだけのコメントは避ける。そのような説明が必要に見える場合は、命名、関数分割、型定義を見直す。
- 公開 API、export される関数、共通 utility、複雑な業務ロジックには、呼び出し側が知るべき前提、返り値、副作用、例外、仕様上の制約を必要に応じて書く。
- 名前と型から役割が明らかな小さな関数には、機械的にコメントを付けない。

## Agent Configuration

- 明示的に依頼されない限り、プロジェクト配下にエージェント用の設定ファイルや設定ディレクトリを作成しない。
  例: `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`, `.codex/`, `.claude/`

## Commands

- ファイル検索は `rg` / `rg --files` を優先する。
- 変更後は、内容に応じて最小限の検証コマンドを実行する。
- 検証コマンドが失敗した場合は、依頼範囲内の変更が原因なら修正し、再実行する。既存不具合、環境問題、依頼範囲外の問題と思われる場合は、要点を報告し、勝手に広範な修正をしない。

## Git

- 明示されない限り commit / push はしない。
- `git reset --hard` や `git checkout --` のような破壊的操作は、必ず確認してから行う。
- 作業前に未コミット変更があっても、それが依頼と無関係なら触らない。
- 変更前後で差分を確認し、意図しない変更が含まれていないか確認する。

## Security

- 秘密情報、トークン、鍵、個人情報をログや回答に露出しない。
- `.env`、秘密鍵、認証情報、個人情報を含むファイルは、明示的な依頼なしに作成・編集・表示しない。
- 新しい依存関係の追加、外部サービスへの送信、認証情報を使う操作は、必要性を説明する。
